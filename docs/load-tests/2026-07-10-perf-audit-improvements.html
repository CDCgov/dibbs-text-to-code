Correctness: no behavioral regression signal

Every augmented eICR's predicted LOINC translation was compared against the expected code for its base test case (10 curated hard cases × 30 salted variants each).

Deterministic within each arm

Pass 1 and pass 2 produced byte-identical match profiles in both arms (60/300 and 47/300) — the result cache returns exactly what the live KNN path computed.

Same hard cases miss in both arms

The same 7 known-hard cases (CBC panel, K+, BUN, POC oxymorphone, VLDL, hep A IgM, MCHC, glucose challenge) missed in all 30/30 variants in both arms — a pre-existing model behavior, untouched by this branch.

Two borderline cases flipped

pCO2 Venous: 30/30 → 18/30 matched; fentanyl screen: 30/30 → 29/30. This accounts for the entire 60-vs-47 delta.

Read the match-rate delta with care. The test salts every candidate text with a unique run/arm marker to force cache misses — so the two arms embedded different strings (…[lt-886f100a-baseline-004] vs …[lt-0f388461-branch-004]), and borderline nearest-neighbor results can flip on the salt alone. The branch arm shows this directly: pCO2 Venous matched on 18 salt variants and missed on 12 within the same arm, same code. The per-arm difference is consistent with salt-induced embedding noise on borderline cases, not a ranking change — but if we want to rule out an effect from the batched-embedding change, the clean check is a fixed unsalted corpus run through both images offline.

What changed on the branch

Dropped the S3 pre-flight HEAD; bounded client timeouts

One fewer round-trip per document and no unbounded hangs under load.

Batched result-cache lookups and embeddings

One OpenSearch mget and one model forward-pass per document instead of per candidate.

Cached the Saxon processor and compiled validator stylesheet

Schematron parsing cost paid once per container, not once per invocation.

Hardened cold start against Hub lookups and cache bloat

The image no longer reaches for Hugging Face Hub at init; augmentation init time dropped 17% on average.

Methodology. Each arm deployed its image, then ran ./scripts/load_test.sh run --arm <label> --docs 300 --passes 2: 300 salted eICRs uploaded to S3 in a 24-way parallel burst (SQS batch size 1, no reserved concurrency, forcing Lambda scale-out), drained fully, then measured from CloudWatch Logs Insights over REPORT lines and the S3 LastModified join (TextToCodeSubmissionV2 → AugmentationEICRV2). Invocation counts matched the document count exactly in every pass, so no foreign traffic contaminated the windows.

Known gap. TTC Lambda cold-start counts came back null from the Logs Insights query in both arms (the report drops null fields), so cold-start init time for the TTC container isn't compared here; the augmentation lambda's cold starts (25 vs 30) confirm containers were recycled for both arms.
